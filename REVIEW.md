# REVIEW.md — правила код-ревью

Чек-лист для ревью PR в `master`. Правила проекта живут в `CLAUDE.md` (корневой,
`apps/api/`, `apps/web/`) — здесь только то, что нужно проверять в диффе, со ссылками
на источник. Расходится дифф с `CLAUDE.md` — прав `CLAUDE.md`, либо PR должен править и его.

## Порядок ревью

1. `gh pr diff <номер>` или `git diff master...HEAD` (три точки — только коммиты ветки).
2. Сначала контракт API и изоляция данных, потом архитектура слоёв, потом стиль.
   Ошибка в первых двух блоках — блокирующая, остальное — комментарии.
3. Проверить, что раздел `## Проверка` в описании PR не врёт: `pnpm lint`, `pnpm typecheck`,
   `pnpm build` и тесты затронутого пакета действительно прогнаны.

Локально то же самое даёт `/code-review` — им удобно прогонять свою ветку до пуша.

## Блокирующее

Эти пункты не мержатся ни при каких «поправлю следующим PR».

### Контракт API

- **Деньги — строки.** `amount: string` на всём пути: DTO (`@IsNumberString()`),
  `shared-types/src/models.ts`, фетчеры, компоненты. `Number()` допустим только внутри
  форматирования для `Intl` (`shared/lib/format.ts`). Арифметика над суммами в виде `number` —
  повод завернуть PR.
- **Суммы всегда положительные**, направление задаёт `type` (`INCOME`/`EXPENSE`/`TRANSFER`).
  Минус у расхода — оформление, а не данные.
- **Даты — ISO-строки** по HTTP (`@IsDateString()`), конвертация в `Date` — в сервисе перед Prisma.
- **`null` и `undefined` в update-DTO различимы:** `undefined` — «не трогать», явный `null` —
  «обнулить». Проверь, что новая логика апдейта не схлопывает их в одно.
- **Enum-ы меняются в двух местах синхронно:** `apps/api/prisma/schema.prisma` (источник истины)
  и `packages/shared-types/src/enums.ts` (ручная копия). Правка одного без другого — блок.
- **`apps/api` не зависит от `@expense-tracker/shared-types`.** Появилась такая зависимость без
  шага сборки у пакета — блок (Nest собирается `tsc` и не возьмёт файлы вне `rootDir`).
- **Изменение контракта отражено с обеих сторон:** поменялся DTO — поменялась zod-схема формы
  на вебе, и наоборот. Ломающее изменение — `!` в заголовке PR и абзац `BREAKING CHANGE`.

### Изоляция данных (`apps/api`)

- **`userId` никогда не приходит от клиента** — только из токена через `@CurrentUser('id')`.
  В Create-DTO его нет; в Update-DTO он отрезан `PartialType(OmitType(CreateDto, ['userId']))`.
- Сигнатуры сервисов — `create(userId, dto)`, `findAll(userId, …)`, `findOne(id, userId)`,
  `update(id, userId, dto)`, `remove(id, userId)`. Запрос без `userId` в `where` — блок.
- **Чужая запись — 404, а не 403** (`findFirst({ where: { id, userId } })`), чтобы не подтверждать
  её существование. `update`/`remove` получают проверку бесплатно, если зовут `findOne`.
- **Ссылки на чужие записи проверяются** — `AssertAccountOwnedQuery` / `AssertCategoryOwnedQuery`
  через `QueryBus`, а не прямой `findFirst` по чужой таблице.
- Новый маршрут **закрыт по умолчанию** (глобальный `JwtAuthGuard`). Появился `@Public()` —
  требуй в описании PR обоснование, почему эндпоинт открыт.
- Пароли — только `UsersService.hashPassword`/`verifyPassword` (scrypt из `node:crypto`).
  Появился bcrypt или ручной хеш — блок.

## Архитектура

### `apps/api`

- Вызов **между** модулями — только через `CommandBus`/`QueryBus`. Инжект чужого сервиса
  напрямую — блок. Внутри своего модуля контроллер зовёт сервис обычным вызовом.
- Сообщение живёт у модуля-владельца данных: `<domain>/cqrs/{commands,queries}/`, класс и его
  handler в одном файле, handler добавлен в `<Domain>CqrsHandlers` из `<domain>/cqrs/index.ts`
  и зарегистрирован в `providers`.
- Модуль строится по шаблону `<domain>.module.ts` + `.controller.ts` + `.service.ts` + `dto/`.
  Репозиторный слой заводится не «на всякий случай» — сейчас он есть только у `users`.
- `PrismaService` инжектится напрямую (модуль `@Global`), импортировать `PrismaModule` не нужно.
- Порядок маршрутов: конкретные пути (`/summary`) объявлены **выше** `@Get(':id')`, иначе 404.
- Нарушение уникальности переводится в 409 через `toDuplicateError` (P2002), а не отдаёт 500.
- Миграция Prisma приложена к тому же коммиту, что и правка схемы.
- Затронут сервис — есть или обновлён `*.spec.ts`; в описании PR указано, что `pnpm --filter
@expense-tracker/api test` прогнан.

### `apps/web`

- **Направление импортов FSD — только вниз:** `app` → `views` → `widgets` → `features` →
  `entities` → `shared`. Импорт соседнего слайса того же слоя — блок.
- **Слайс импортируется через свой `index.ts`** (`@/features/auth`, `@/entities/session`).
  Путь внутрь слайса допустим только там, где баррель тянет несовместимый рантайм, и только
  с комментарием: `middleware.ts` → `@/entities/session/model/token`, Route Handlers →
  `@/features/auth/model/schemas` и `@/shared/api/route-error`. Новое исключение без комментария
  и без объяснения в PR — блок.
- Файлы в `src/app/` тонкие: `page.tsx` экспортирует компонент из `views` и свою `metadata`.
  Разметка экрана прямо в `app/` — повод потребовать слайс в `views/`.
- **Фетчер сущности принимает токен аргументом**, а не читает cookie сам: иначе модуль потянет
  `next/headers` и баррель станет непригоден для `'use client'`. Cookie разбирает вызывающий
  Server Component через `getSessionToken()`.
- Правильный клиент под задачу: `api`/`apiFetch` — серверный код в Nest (токен опцией `{ token }`),
  `routeFetch` — браузер в свои Route Handlers (cookie уходит сама). Прямой `fetch` в компоненте —
  комментарий.
- Ошибки Route Handler разворачиваются через `toErrorResponse` из `@/shared/api/route-error`,
  чтобы статус и текст от Nest дошли до формы как есть.
- Токен **не утекает в браузер**: Route Handler отдаёт профиль, но не `access_token`;
  cookie остаётся httpOnly. Любая передача JWT в клиентский компонент — блок.
- Страница без авторизации добавлена в `PUBLIC_ROUTES` (`shared/config/routes.ts`), а не только
  в middleware. Редирект по внешнему параметру (`from`) проверен на относительность.
- Формы — `react-hook-form` + `zod`, схема в `model/schemas.ts` слайса, одна и та же на клиенте
  и в Route Handler (`safeParse`). Ошибка уровня формы (401/409/сеть) — через `FormError`,
  а не в поле.
- Компонент shadcn добавлен CLI и **импорт `cn` починен** на `@/shared/lib/utils` (CLI пишет
  `from "cn"`); мусорный npm-пакет `cn` в `package.json` — блок. Цвета правятся токенами
  в `src/app/globals.css`, а не классами в компонентах.

## Git и оформление PR

- Одна ветка = одна фича; несвязанные правки — повод попросить вынести в отдельный PR.
- Имя ветки — `<тип>/<kebab-case>`, с префиксом пакета, если фича пакетная
  (`feature/web-dashboard-overview`).
- Коммиты атомарные, по Conventional Commits: заголовок на английском, в повелительном
  наклонении, со строчной буквы, до 72 символов, без точки. Правки `apps/api` и `apps/web`,
  не связанные общей фичей, разнесены по коммитам. Сгенерированные файлы (`pnpm-lock.yaml`,
  миграции) — в коммите со своей причиной, а не отдельным «chore».
- Ветка обновляется от `master` **rebase**, а не merge-коммитом.
- Заголовок PR — по сути изменения целиком, а не копия последнего коммита.
- Описание PR по скелету из корневого `CLAUDE.md` и **отражает дифф, а не намерение**:
  список по фичам, маршруты в виде `МЕТОД /путь — что делает`, обоснование неочевидных решений,
  раздел «Осталось за рамками». Пустые разделы выкинуты, а не оставлены заглушками.
  UI-изменение без скриншота — комментарий.

## На что не тратить ревью

- Форматирование — это `pnpm format` (prettier), а не комментарии в PR.
- Стилевые предпочтения без ссылки на правило из `CLAUDE.md`: если хочется закрепить, сначала
  правь `CLAUDE.md`, потом требуй.
- Заглушки, честно перечисленные в разделе «Осталось за рамками», — они согласованы,
  а не забыты.
- Изменения в \*.lock файлах
