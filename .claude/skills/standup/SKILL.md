# Стендап-отчёт за вчера

Отчёт собирается **только из git** — коммиты, их диффы и состояние рабочего дерева.
Ничего не выдумывай: если чего-то нет в диффе, этого нет и в отчёте.

## 1. Определи период

Отчётный день — вчерашний, окно `[вчера 00:00, сегодня 00:00)`:

```bash
git log --all --since="yesterday 00:00" --until="today 00:00" \
  --author="$(git config user.name)" --date=iso \
  --pretty=format:'%h%x09%ad%x09%d%x09%s'
```

- Если коммитов **нет** — не сдавайся сразу: возьми предыдущий рабочий день
  (`--since="3 days ago 00:00"`) и явно напиши в отчёте, за какую дату он на самом деле.
  Понедельник → отчёт обычно за пятницу.
- Автор фильтруется по `git config user.name`. Если фильтр дал пусто, а коммиты за период
  есть — прогони без `--author` и отметь в отчёте чужие коммиты отдельно.
- `--all` нужен, чтобы попали коммиты из фиче-веток, ещё не влитых в `master`.

## 2. Разбери, что именно сделано

Для **каждого** коммита из выборки посмотри реальный дифф, а не только заголовок:

```bash
git show --stat <hash>          # какие файлы и на сколько строк
git show <hash>                 # сам дифф, если по стату непонятно
```

Мердж-коммиты (`%d` покажет merge) в список работ не идут — учитывай их только как факт
влития ветки. Что читать в диффе:

- новые эндпоинты Nest и Route Handlers Next — выпиши как `МЕТОД /путь`;
- новые модули/слайсы FSD, миграции Prisma, изменения контракта в `shared-types`;
- тесты: появились ли, что покрывают;
- чистый рефакторинг/доки отмечай отдельно от функциональных изменений.

## 3. Добавь незавершённое

```bash
git status --short
git stash list
git log --oneline master..HEAD   # свои коммиты в текущей ветке, ещё не в master
```

Незакоммиченные изменения и неслитые ветки — это раздел «в работе», а не «сделано».

## 4. Собери отчёт

Выводи в чат, по-русски, markdown. Структура:

```markdown
## Стендап за <дата, напр. 21 сентября (пн)>

**Коротко:** 1–2 предложения — главный итог дня.

### Сделано

- **<Фича/задача>** (`<scope>`) — что именно и зачем. Коммиты: `abc1234`, `def5678`.
  - детали, если их стоит проговорить на дейли (решения, нюансы контракта)

### Эндпоинты и маршруты

- `POST /api/transactions` — что делает

### В работе

- `feature/web-dashboard` — 3 коммита, не влита в `master`
- незакоммичено: `apps/web/src/...` (что там)

### Блокеры

- ...
```

Правила вывода:

- Группируй **по задачам/фичам, а не по коммитам**: несколько коммитов одной фичи — один пункт.
- Порядок — по значимости: функциональность выше рефакторинга, рефакторинг выше доков.
- Пустые разделы («Эндпоинты», «Блокеры», «В работе») выкидывай, а не оставляй заглушками.
- Хеши коммитов — короткие, в бэктиках; на дейли по ним удобно поднять детали.
- Формулировки — человеческие, для устного пересказа: «доделал фильтры на дашборде»,
  а не «feat(web): add dashboard filters».
- Блокеры бери только из фактов (упавшие тесты, TODO в диффе, недоделанная ветка) —
  не додумывай.

## Аргументы

Скилл может получить аргумент с периодом: `/standup за неделю`, `/standup за 2026-09-15`.
Тогда меняй только окно в `--since/--until`, заголовок отчёта и всё остальное — по тем же правилам.
